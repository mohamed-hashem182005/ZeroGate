08FLOWS / TERMINATION

How access ends
in under two seconds.

The score is recomputed on a 60-second heartbeat and on any posture, policy, device, or anomaly event. When it falls below 40, the Policy Administrator closes the proxy session and revokes the SSH certificate. A repeated kill returns the existing result. The audit record is written even if the user has already gone.

The arithmetic in the figure

The session started at 89. Disk encryption is turned off (−25), transfer volume reaches 15× the user's baseline (−20), and two heartbeats are missed (−10). The score is 89 − 25 − 20 − 10 = 34. The band is DENY / KILL. No human is asked; the threshold is explicit and the evidence is recorded.

The example is deliberately simple. The point is not the exact weights; it is that every point is attributable to a named signal, the category caps prevent one category from dominating, and a hard gate would have stopped the session before the arithmetic. The risk report contains the full catalog and the worked examples.

What kill actually does

Killing is not a database flag. It is a set of obligations carried out across the proxy, the SSH CA, the notification channel, and the audit chain. The Policy Administrator is responsible for all of them. The API is idempotent: a second kill with the same idempotency key returns the same result and already_killed: true.

The race

In-flight requests

The proxy keeps a session decision cache with a TTL of at most one second. A kill invalidates the entry before the next request is admitted. A request already in flight may finish; it cannot start a new one. The residual window is bounded and measured.

The residue

Certificates and caches

The certificate revocation list is published every 60 seconds. Short certificate lifetimes bound the gap. The proxy cache is invalidated immediately. The portal session is marked killed; the cookie alone cannot revive it.

What the user sees

The portal shows a plain-language explanation: the session ended because device encryption was disabled, the score fell below the threshold, and the correlation id is req_9b3e2a. The admin alert includes the same id and the top three reasons. The audit event includes the full signal list, the policy version, the model version, and the input hash.

Kill is terminal

A killed session cannot be resumed by re-authenticating into the same session. The user may start a new request, which is scored from scratch. The old session remains in the audit chain as KILLED; it is never deleted or overwritten.

Failure modes

  • CA unreachable: the kill still closes the proxy session; the revocation is retried and the alert says the certificate is pending revocation.
  • Audit unavailable: the kill is not reported as complete until the event is appended; the API returns a retryable error.
  • Duplicate kill: idempotent; the second call returns the first result.
  • Heartbeat in flight: the kill decision wins; a late heartbeat cannot move the session out of KILLED.
  • Notification failure: the session still ends; the notification is retried and the failure is audited.
