The OpenAPI 3.1 document is the interface between the portal, the two enforcement points, the Policy Administrator, and the admin console. It exposes 42 paths and 53 operations over twelve tags. The central call is POST /v1/authorize; every enforcement path speaks the same decision shape.

post /v1/sessions/{sessionId}/kill

The idempotent kill

The kill closes the proxy session, revokes certificates, and records the event. A retry with the same idempotency key returns the first result and sets already_killed.

{
  "session_id": "ses_01J8Z8",
  "state": "KILLED",
  "killed_at": "2026-10-14T10:31:07Z",
  "revoked_certificate_ids": ["sshcert_77a1"],
  "audit_id": "evt_01J8ZA7Q",
  "already_killed": false
}

Conventions

01 / Versioning

Everything under /v1

Paths are versioned. Additive changes are allowed inside a version; a breaking change requires a new prefix. Deprecated operations carry a deprecated: true flag.

02 / Auth

Cookie or bearer

Browsers use the zg_session cookie. The CLI and internal services use a short-lived bearer token. Public operations are limited to health, the two passkey ceremonies, the CA public key, and the SPA knock.

03 / Mutations

Idempotency keys

Every state-changing operation accepts an Idempotency-Key. Replaying the same key with the same body returns the original result; a different body returns 409.

04 / Errors

One envelope

Every error is a Problem with code, message, optional details, and a correlation_id. The UI shows the correlation id, not a stack trace.

05 / Lists

Cursor pagination

List endpoints take limit and cursor and return PageInfo. Cursors are opaque and stable for the life of the query.

06 / Time

ISO 8601, UTC

All timestamps are RFC 3339 strings in UTC. Durations are integer seconds. The API never returns a local-time string.

Authentication

Browser

sessionCookie

An HttpOnly, Secure, SameSite=Lax cookie named zg_session, minted after a successful passkey verification. The server-side session has a 15-minute idle timeout and an 8-hour absolute lifetime.

CLI / service

bearerAuth

A short-lived JWT signed by the identity service. The SSH helper and internal services use it. It carries the user, device, and role claims; it is never stored in a URL or a log.

Five operations are public: GET /v1/health, POST /v1/auth/passkey/options, POST /v1/auth/passkey/verify, GET /v1/ssh/ca/public-key, and POST /v1/spa/knock. Everything else requires a session or a bearer token and is subject to rate limits.

Error model

The error envelope is the same for validation, authentication, policy, and rate limiting. A client can branch on error.code without parsing prose, and a support engineer can correlate the request with the audit chain through correlation_id.

Validation

The spec is linted with @redocly/cli using the recommended ruleset and checked by a local resolver that walks every internal $ref. The build fails on a missing reference, a duplicate operation id, or an undocumented 4XX on an operation that requires authentication.

Scope of the contract

The API covers web apps and SSH servers only. There is no Kubernetes, database, email, SWG, CASB, DLP, or multi-tenancy surface. Vault operations are included because SecureVault is core; they are a separate encrypted store, not part of the access-control schema.
