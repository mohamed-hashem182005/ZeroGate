06FLOWS / SSH

Thirty minutes,
one host, no static key.

The SSH path replaces long-lived keys with a short-lived certificate that is bound to one principal, one host, and one source address. The CA signs only after the Policy Engine allows. The server trusts only the CA. A stolen certificate expires on its own; a stolen laptop holds no permanent key.

The shape of the exchange

The helper is deliberately boring. It generates an ephemeral key pair, asks the CA for a certificate, and then hands the certificate to the system SSH client. It does not store the private key, edit authorized_keys, or keep a fallback key. If issuance fails, the connection fails with a reason code the user can act on.

The CA is the second enforcement point. It authenticates the user and device, resolves the target resource, and calls POST /v1/authorize with action ssh. The engine returns an allow with a TTL and obligations. The CA signs only what the decision permits: one principal, one host, one source address, and a validity window of about 30 minutes.

What is inside the certificate

An OpenSSH certificate is a signed statement about a public key. The interesting design work is in the fields: the key id makes the certificate traceable, the principals limit it to one account, the validity window limits its life, the critical options bind it to a source address, and the extensions keep the session narrow. The CA key stays in an HSM or equivalent; the signing operation is the only thing that touches it.

Why short-lived

Expiry is the default revocation

A certificate that lives for 30 minutes needs no long-lived revocation list to be safe. The CA still publishes a revocation list every 60 seconds for the cases that need immediate action, but the common case is simply time.

Why bind the source

A copied blob is not a copied session

The source-address critical option ties the certificate to the address that requested it. A replay from another network fails at the host even before the revocation list is consulted.

Failure paths

The happy path is only half the design. The helper must distinguish “the policy said no” from “the CA is down” from “the host rejected the certificate”, because the user's next action is different in each case. The API returns a stable reason code and a correlation id; the helper prints both.

Single Packet Auth is a stretch goal

The main path keeps the SSH port reachable for the lab. The stretch goal adds a signed single packet that opens the port for one source address for a few seconds. It is deliberately not part of the core sequence: the certificate path must work without it.

What the host checks

The host is configured to trust the ZeroGate CA, not a file of employee keys. On connection it verifies the CA signature, the validity window, the principal, the source address, and the revocation state. It does not call the Policy Engine. That is the point of the certificate: the decision happened at issuance, and the artifact carries the constraints.

When the session is killed, the Policy Administrator revokes the certificate and the CA publishes the revocation within 60 seconds. The short lifetime bounds the residual risk if the publication is delayed. The audit chain records the issuance, the host, the principal, the serial, and the revocation.
