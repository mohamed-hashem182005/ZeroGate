# مشروع ZeroGate — وسيط الوصول بالثقة المعدومة (Zero Trust Access Broker)

مشروع تخرج مبني وفق معيار **NIST SP 800-207**، يوفر حماية متكاملة لتطبيقات الويب الداخلية وخوادم Linux عبر SSH، بدون الاعتماد على كلمات مرور أو عناوين IP، بل من خلال المصادقة عبر مفاتيح المرور البيومترية (FIDO2 Passkeys)، وشهادات SSH قصيرة الأجل، ومحرك تقييم مخاطر مستمر وشفاف مدعوم بالذكاء الاصطناعي، مع سجل تدقيق مشفر غير قابل للتلاعب (Hash-Chained Audit Log).

## 🎯 فكرة المشروع ومحاوره الأساسية

يقوم نظام ZeroGate بالتحقق الصارم من كل طلب وصول بناءً على:
- **الهوية:** مصادقة بيومترية باستخدام مفتاح مادي FIDO2 عبر معيار WebAuthn (لا تخرج المفاتيح الخاصة من الشريحة الآمنة).
- **صحة وسلامة الجهاز (Device Posture):** فحص حالة تشفير القرص، وكسر الحماية (Root / Jailbreak)، وإصدار نظام التشغيل.
- **درجة الثقة والمخاطر (Risk & Trust Scoring):** نموذج جمعي شفاف (0 إلى 100) يبدأ من 100 مع خصومات محددة لكل إشارة خطر، بالإضافة إلى تعديل سلوكي مقيد من نموذج تعلم الآلة (بحد أقصى −15 نقطة)، ولا يلغي أبدًا قواعد الأمان الصارمة (Hard Gates).
- **وصول SSH محكوم زمنياً:** إصدار شهادات SSH تنتهي تلقائياً خلال 5 دقائق (300 ثانية)، بدون مفاتيح SSH دائمة على الأجهزة.
- **قطع الجلسات لحظياً (Mid-Session Kill):** إنهاء الوصول فور حدوث ارتفاع في مؤشرات الخطر أثناء الجلسة المفتوحة.
- **سجل تدقيق مشفر (Tamper-Evident Hash Chain):** سلسلة كتل تدقيقية بروابط SHA-256 تكتشف فوراً أي محاولة تعديل أو حذف أو تلاعب بأي قرار سابق.

## 🗺️ خطة التنفيذ وتوزيع المراحل

المشروع مصمم ليمر بخمس مراحل رئيسية لتفادي تعطل الفرق عن بعضها:

1. **المرحلة الأولى — البنية التحتية الأساسية (الأسابيع 1-2):**
   - بناء ونشر مخططات قواعد البيانات PostgreSQL (الهوية، الوصول، والتدقيق).
   - تجهيز بيئة المعمل الافتراضية (Lab Environment) وشبكة الخوادم المعزولة.
   - بناء الهيكل العام لواجهات البرمجة (OpenAPI Contract Skeleton).

2. **المرحلة الثانية — المصادقة والتحكم بالوصول (الأسابيع 3-4):**
   - محرك القرارات المركزي `POST /v1/authorize`.
   - إعداد المصادقة عبر FIDO2 Passkeys وبوابة الدخول للمستخدمين.
   - تشغيل سلطة شهادات SSH قصيرة الأجل (SSH CA).
   - تشغيل البروكسي العكسي لتطبيق القرارات (PEP).

3. **المرحلة الثالثة — الأمان وإدارة المخاطر (الأسابيع 5-6):**
   - محرك حساب درجات الثقة والمخاطر (القواعد المحددة).
   - تدريب ونشر نموذج الكشف عن الشذوذ السلوكي (ML Anomaly Model) وتوثيقه.
   - ربط وتشفير سجل التدقيق التراكمي (Hash-chained Audit Log).
   - تقسيم واستعادة أسرار الخزنة عبر خوارزمية شامير (Shamir's Secret Sharing).

4. **المرحلة الرابعة — واجهات الإدارة والأدوات العميقة (الأسابيع 7-8):**
   - لوحة تحكم المسؤول (إدارة السياسات، الأجهزة، والجلسات الحية، والقطع الفوري).
   - لوحة قياس زمن الاستجابة المباشر (Latency Dashboard) للتأكد من تحقيق المستهدفات.
   - تطبيق الخزنة المكتبية (SecureVault Desktop App).
   - عميل فحص صحة الجهاز الذي يعمل في الخلفية (Device Posture Agent).
   - أداة الطرفية المساعدة لـ SSH (SSH Helper CLI).

5. **المرحلة الخامسة — سيناريوهات الهجوم والتكامل النهائي (الأسابيع 9-10 فما بعد):**
   - إخفاء منافذ SSH عبر حزم المصادقة الأحادية (Single Packet Authorization).
   - لوحة محاكاة الهجمات (Attack Demo Panel) لاختبار التصدي الحي للهجمات.
   - اختبارات الاختراق الشاملة وضبط الأداء والتأكد من تحقيق معايير سرعة الاستجابة.

## 🎯 الأهداف القياسية للأداء (Performance Targets)

يجب على الفرق اختبار أنظمتها للتأكد من الالتزام بالأرقام المستهدفة التالية قبل يوم المناقشة:
- **زمن تسجيل الدخول بالكامل (Passkey Login):** p95 ≤ 3.0 ثوانٍ.
- **زمن اتخاذ قرار الوصول غير المخزن (Uncached Authorization):** p95 ≤ 100 ميلي ثانية.
- **زمن التحقق من القرار المخزن على البروكسي (Cached Decision):** p95 ≤ 10 ميلي ثانية.
- **زمن إصدار شهادة SSH:** ≤ 2.0 ثانية.
- **صلاحية شهادة SSH:** 5 دقائق بالضبط (300 ثانية).
- **مهلة خمول الجلسة (Idle Timeout):** 15 دقيقة، والحد الأقصى المطلق 8 ساعات.
- **زمن كتابة سجل التدقيق المشفر:** ≤ 20 ميلي ثانية.
- **زمن استدلال نموذج الذكاء الاصطناعي:** ≤ 100 ميلي ثانية.
